## What is genuinely working

- Loopback Node daemon with SQLite WAL, one-time bootstrap, session cookie, CSRF check and Host allow-list.
- Offline mock provider, Anthropic adapter, and OpenAI-compatible adapter. Provider profiles use the OS secret-store abstraction and affect runtime default selection; native macOS Keychain has been smoke-tested while Linux/Windows/VS Code vault integration remains outstanding.
- Bounded runtime supports workspace read/search/write/edit, git inspection, task/memory actions, run-scoped worker messaging and shared blackboard tools. Approval continuations are encrypted at rest and restart-recoverable; the server integration test exercises parent-run restoration after an injected provider failure.
- Async supervisor planning validates provider-generated plans against active agents, falls back to deterministic plans, executes dependency waves with at most three workers at once, and persists child runs/subtasks/results/messages/blackboard values and live events.
- Run inspector shows dependency-stage cards, live child events, shared blackboard data, and final supervisor output. Tests cover the complete mock portfolio plan and runtime message/blackboard behavior.
- Some dashboard mutations are real: tasks, memory creation, approval/proposal status, provider profile operations, and run creation. Other pages remain catalog/display views.
- Error responses include request ID and structured fields for handled HTTP errors.

## Only partially working

- Provider support/storage/configuration, runtime, router, tools, policy, approval workflow, runs/timeline, dashboard, pagination, error handling and SSE as detailed in the table. The UI does not make their missing backend behavior complete.

## Completely missing

- Agent-initiated delegation with depth/cycle/budget enforcement, two-stage routing, large agent/skill catalogs, shell sandbox, browser/desktop tools, Gmail/OAuth, MCP, Forge, Janitor, version history/rollback, signed updater, VS Code extension, router training, and scale/accessibility/browser E2E suites.

## Five highest-priority implementation tasks

1. **Secure cross-platform provider manager:** native keychain adapters (macOS/Windows/Linux), eliminate process-argument secret exposure, real profile configuration, provider types, timeouts, usage, tests, and status.
2. **Tool registry and sandbox:** schema-validated registry with truthful availability, file edit/search, git, shell isolation, output caps, cancellation, taint and audit enforcement.
3. **Supervisor + multi-agent completion:** agent-initiated delegation, depth/cycle/budget enforcement, retry/resume, message acknowledgement, and recovery of independent in-flight workers.
4. **Scale catalogs and two-stage router:** structured 100+ agent and 200+ skill catalog, family routing, benchmark corpus and router training pipeline.
5. **Real-time dashboard and verification:** complete graph edges, artifacts and approval detail; reconnectable SSE cursors; pagination/filtering; Playwright/axe and scale scenario tests.

## Exact provider/API-key changes required

1. Replace the two-type `providers` table with profile metadata fields: provider ID/type, model/base URL, organization/project, temperature, max tokens, timeout, enabled, key reference, timestamps and status counters. Keep secret values exclusively in a platform secret-store abstraction.
2. Implement macOS Keychain, Windows Credential Manager, Linux Secret Service and extension `SecretStorage`; eliminate password in process arguments. Add an encrypted fallback only with a separately protected key.
3. Support typed adapters for Ollama, Anthropic, OpenAI, OpenAI-compatible, Azure, Gemini, Mistral, Groq, Together, DeepSeek and custom endpoints, with safe timeouts and structured provider errors.
4. Complete CRUD/test/default routes and UI fields; never return keys, display masked suffix, rotate/delete credentials, test without logging request contents, and persist last-tested/latency/error/usage.
5. Route runtime provider choice through the selected profile and test every adapter using fake HTTP servers. Do not count profile CRUD as provider integration until a run uses it.

## Exact multi-agent orchestration changes required

1. Add migrations for `subtasks`, `agent_runs`, `agent_messages`, `blackboard_entries`, `tool_calls`, `artifacts`, `agent_versions`, `skill_versions`, `routing_log` and metrics, with run/status/time indexes and foreign keys.
2. Give planner a structured plan output schema: supervisor, selected workers, dependencies, parallel groups, tools/skills, risk and approvals. Clamp every ID/permission to the live catalog.
3. Persist and schedule subruns with bounded concurrency (implemented), then add a shared step/token/cost budget, depth/cycle detection for worker-initiated delegation, retry and durable restart recovery. Make workers read assigned task and authorized blackboard context only.
4. Add event bus persistence for every lifecycle/message/tool/approval/artifact/test event (run and worker lifecycle/message/blackboard events are implemented). SSE still needs durable cursor replay and reconnect semantics.
5. Implement approval as a durable suspension: exact original args are displayed, decision is hash-bound, timeout denies, approved operation executes once, its result resumes the same model loop, and denial is returned as a tool result.
6. End-to-end test a portfolio website task: plan, UX/frontend/backend/security/accessibility/test/review/doc agents, real workspace artifacts, approved side effects, persisted messages/blackboard/events, tests and final report.

## Exact live dashboard changes required

1. Replace catalog-only cards with endpoints backed by real agent runs, worker subtasks, tool calls, message/blackboard records, artifacts, approvals and test results.
2. Add chat/run creation, cancel/retry/reassign, agent detail and graph, context-segment timeline, approval detail/resume, file artifact list/diff and blackboard/message views.
3. Drive UI via reconnectable SSE/WebSocket cursor; update agent nodes and run state without refresh; expose errors and blocked states.
4. Add server-side filtering/cursor pagination and virtualization. Display unavailable tools/providers as unavailable rather than actionable.
5. Add keyboard/focus/contrast support and Playwright + axe tests against seeded large data and the full orchestration scenario. The current dashboard is plain static HTML/CSS/JS, not Vite/React/TypeScript.
